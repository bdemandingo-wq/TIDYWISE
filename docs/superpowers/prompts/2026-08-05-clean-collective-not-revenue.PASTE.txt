In the jointidywise project, mark Clean Collective's plan payments as not
TidyWise subscription revenue, exactly the way Clean Castillo and the
website-build payments were handled on 2026-08-05. Commit it as a migration
file and confirm it RAN against the live database, not just that the file
exists.

────────────────────────────────────────────────────────────────────────
WHY
────────────────────────────────────────────────────────────────────────

Clean Collective is a co-venture of the founder's, not a customer. The $97 is
money moving between his own businesses, so counting it as plan revenue
overstates what the CRM has earned from other people.

This is the same category as two corrections already applied in migration
20260805062431:

  "Clean Castillo - personal, paid by a friend of the founder."
  "Pointpolishcleaners / Lumi Elevated - payment for website build work,
   not a plan."

Both set counts_as_cash = false and appended the reason to correction_basis,
leaving the rows in place. billing_events is append-only — the row stays, it
just stops counting. Do the same here. Do NOT delete anything.

Clean Collective has exactly two cash-counting plan events:

  2026-06-26  invoice.paid       $0.00
  2026-07-03  charge.succeeded  $97.00

The $0 invoice matters as much as the charge: leaving it counting would keep
Clean Collective in billing_plan_payers as a zero-value payer, which is the
same misclassification in a different place.

────────────────────────────────────────────────────────────────────────
WHAT TO RUN
────────────────────────────────────────────────────────────────────────

update public.billing_events b
set counts_as_cash   = false,
    correction_basis = coalesce(b.correction_basis || ' | ', '')
      || 'counts_as_cash=false 2026-08-05: not TidyWise subscription revenue. '
      || 'Clean Collective - founder co-venture, money moving between his own businesses.',
    corrected_at     = now()
from public.organizations o
where o.id = b.organization_id
  and o.name = 'Clean Collective'
  and b.counts_as_cash
  and coalesce(b.revenue_stream_corrected, b.revenue_stream) = 'plan';

Keyed on the organisation rather than on the two event ids, so a later-synced
payment from the same org is caught by a re-run instead of silently counting.
Safe to run more than once — `and b.counts_as_cash` means already-corrected
rows are skipped and their correction_basis is not appended to twice.

Do NOT touch merchant_cleaning rows for this org. Clean Collective's own
cleaning customers paying Clean Collective is real revenue for that business;
it simply is not TidyWise plan revenue, and it is already a separate stream.

where confidence in ('certain','probable')
