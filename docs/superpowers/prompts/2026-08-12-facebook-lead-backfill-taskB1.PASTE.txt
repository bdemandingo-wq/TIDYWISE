=== STEP 1: THE MIGRATION ===

alter table public.leads add column if not exists backfilled_at timestamptz;

comment on column public.leads.backfilled_at is
  'Non-null when this row was imported from a historical source rather than '
  'arriving live. NULL means it arrived live. Outbound speed-to-lead '
  'automation MUST filter on `backfilled_at is null` - a backfilled row can be '
  'weeks old, and texting that person as a fresh enquiry is a real-world '
  'mistake, not just bad data.';

-- The exact predicate a future speed-to-lead notifier will run, made cheap now.
create index if not exists leads_live_recent_idx
  on public.leads (organization_id, created_at desc)
  where backfilled_at is null;


=== STEP 2: STOP CHECK - RUN THIS AND READ THE RESULT BEFORE REPORTING SUCCESS ===

select tgname, pg_get_triggerdef(oid) as definition
from pg_trigger
where tgrelid = 'public.leads'::regclass
  and not tgisinternal;

*** IF ANY RETURNED TRIGGER IS A BEFORE INSERT OR BEFORE UPDATE TRIGGER THAT
*** SETS, OVERWRITES OR OTHERWISE TOUCHES created_at:
***
***   STOP. Do not report this task as done. Do not proceed to anything else.
***   Paste the full trigger definition into your reply and wait for me.

Why this matters more than it looks. The next step after this migration imports
~29 real Facebook leads that arrived in JULY, writing their true arrival dates
into created_at. A BEFORE INSERT trigger that sets created_at = now() would
silently overwrite every one of those dates. The import would report complete
success while producing exactly the wrong data: 29 leads that all look like they
arrived today. Since the entire point of the import is that a lead's age is the
most important thing about it, that failure would defeat the whole exercise -
and it would be invisible until someone noticed the dates were all identical.

So this is not a formality. If the trigger exists, the plan changes before
anything is imported.

If there are no non-internal triggers on public.leads, say so explicitly -
"no rows returned" is the answer I need, not silence.
