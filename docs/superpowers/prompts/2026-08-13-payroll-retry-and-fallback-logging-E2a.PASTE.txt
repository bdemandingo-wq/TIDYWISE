=== WHAT MUST NOT CHANGE — three non-obvious invariants ===

1. THE ESCALATION CONDITION.

     if (escalated.ok && escalated.sender.usedFallback && !resolved.sender.usedFallback)

   `!resolved.sender.usedFallback` is the clause that looks redundant and is not.
   It means "the FIRST attempt used the org's own identity, so there is somewhere
   better to escalate to." When the first attempt already went out from the
   platform sender — the ~22 orgs with no email settings row at all — there is no
   better identity available, and that org correctly falls through to the plain
   retry. Dropping the clause would make those orgs "escalate" to the identity they
   already used, and then log a second fallback row for a single send.

2. BORROWING THE PLATFORM KEY IS NOT A FALLBACK.

   An org with a valid From address but no Resend key of its own sends from its OWN
   From using the platform key, and resolveSender returns `usedFallback: false`.
   Nothing is logged for that case, and nothing should be. The recipient sees an
   unchanged sender, so nothing has degraded. If that were logged, most orgs would
   appear in org_email_send_failures as misconfigured and bury the ones that
   genuinely are.

   In the new code this means `pendingFallbackReason` stays null for those orgs.

3. A TOTAL SEND FAILURE STILL WRITES NO org_email_send_failures ROW.

   After these edits, an org whose send fails on both attempts produces no row in
   org_email_send_failures. That is unchanged from today's behaviour and it is
   intentional here. The failure is not lost — email_send_log gets status 'failed'
   with the error message, which is how it is already reported.

   Adding a `fell_back_to IS NULL` row on hard failure is a genuine improvement and
   it is NOT part of this task, because that column is exactly what the owner-facing
   health banner counts. Starting to write those rows would begin alarming owners,
   which is a product decision, not a cleanup. Leave it. Mention it in your reply if
   you like.

  const warnPlatformSender = (reason: string) => {

      `(${reason}). The org's own email identity is not usable.`,
