=== WHY THE CLAIM IS A SERVER FUNCTION AND NOT A CLIENT INSERT ===

`public.organizations`' INSERT policy is `(auth.uid() = owner_id)` and does NOT
enumerate columns, so an authenticated user can already write any column on
their own org row. If attribution were client-writable a user could name any
referrer, mark themselves 'qualified', or grant themselves months.

So the four org_referral* tables carry SELECT policies only, and every write
goes through the service role. The client sends an org id and a code. These
functions decide everything else.

=== WHAT THIS FUNCTION DOES ===

Called with a referral id. It:

  1. grants the referrer one month for that referral,
  2. checks whether they have now reached THREE referrals in good standing and,
     if so, grants two ADDITIONAL months, once, ever,
  3. reconciles the total months owed into one Stripe coupon on the referrer's
     subscription.

Three referrals earns 3 + 2 = 5 months. The bonus is ON TOP of the three
already earned, not instead of them.


=== THE LEDGER ===

`public.org_referral_credits` is the source of truth:

    months_granted   — everything ever awarded to this org
    months_redeemed  — months actually consumed by a $0 invoice
    active_coupon_id — the coupon currently on the subscription

Months still owed is `monthsOwed(granted, redeemed)` from
`_shared/referral-eligibility.ts`. It CLAMPS AT ZERO — do not write your own
subtraction. Redemption is counted from webhook events, so a double delivery
can push redeemed past granted, and a negative `duration_in_months` is rejected
by Stripe outright.


=== THE LOGIC, IN ORDER ===

1. Accept `{ referral_id }`. Service role. This is called server-to-server from
   stripe-invoice-webhook, so require the cron/internal secret the other
   internal functions use rather than a user JWT.

2. Load the referral. Proceed ONLY if `status = 'qualified'` and
   `referrer_reward_granted_at IS NULL`. Anything else: return
   `{ outcome: 'already_granted' }` with 200. This is the idempotency guard —
   Task 6 may call this more than once for the same referral.

3. Skip a lifetime referrer. Use `isMonthlyPlan(plan_type)` from the shared
   module. A lifetime org has no subscription to discount. Set the referral to
   'rewarded' with a note and return `{ outcome: 'referrer_not_monthly' }` —
   do NOT error, and do NOT leave it 'qualified' forever.

4. Grant the per-referral month: `months_granted = months_granted + 1` on
   org_referral_credits for the REFERRER. Stamp
   `referrer_reward_granted_at` and set the referral to 'rewarded' IN THE SAME
   STEP, so a retry cannot double-grant (step 2 then short-circuits).

5. THE BONUS. Recount from scratch — do not trust a stored counter:

   - load every org_referrals row where referrer_org_id = this org
   - for each, get the referred org's CURRENT subscription status from
     `stripe_subscriptions`
   - call `isInGoodStanding({ status, paidInvoiceCount, subscriptionStatus })`
     from the shared module for each
   - count the trues
   - `bonusMonthsOwed(count, bonusAlreadyGranted)` decides the rest

   Recounting at every vesting event is deliberate: a referral can fall OUT of
   good standing between converting and the third one arriving, and a stored
   counter would not notice.

   If it returns 2, insert `org_referral_bonuses` (months 2, and the qualifying
   referral ids) and add 2 to months_granted. The table has
   UNIQUE(organization_id), so "once ever" is enforced by the database — treat
   23505 there as "already granted", not an error.

6. RECONCILE THE COUPON. Compute `monthsOwed(granted, redeemed)`. If zero, do
   nothing. Otherwise:

   - create a coupon: `percent_off: 100, duration: 'repeating',
     duration_in_months: <months owed>`
   - apply it to the referrer's subscription, REPLACING any coupon currently
     recorded in `active_coupon_id`
   - store the new coupon id in `active_coupon_id`

   Replacing rather than stacking is why the ledger exists. Do not apply a
   second coupon.

7. Always return 200 with an `outcome`. Never 500 for a business condition.
   Outcomes: `granted` | `already_granted` | `referrer_not_monthly` |
   `nothing_owed`.
